## 目的、適用情境與現有內容分工

讓兩人理解「我想怎麼安排、目前願意且做得到什麼、共同花費怎麼確認，以及生活安排誰負責準備與追蹤」。不是金融素養、財務能力、信用、節儉人格或關係成功率測驗；不替兩人選投資、貸款、保險、稅務或帳戶方案，不執行任何金融操作。

直接問「你」，不用「這個人」的人物相似程度。不預設已婚、同居、共同帳戶或固定共同支出；沒有本輪相關經歷可明示，不以過去關係或猜未來代答。所有性向與性別認同共用題目與規則，沒有身分欄位或性別分工。生育不在範圍。

已有日常三觀的DV01旅行分攤、DV02共同餘裕、DV09個人購物，以及know-life四題問答。本稿往「提出花費先說什麼、確認範圍、本人願意集中處理什麼、超出負擔怎麼保留、條件變動、準備／追蹤工作」延伸，避免只改字重發相同情境。分攤原則仍與DV01有概念交集，12題是否需要更精簡或擴充須另審閱。

題目不要求填收入、資產、負債、帳戶、金額、信用分數或私人財務文件。共用花費只是題目中的前提，不表示使用者已有這種安排；選答不是付款承諾、帳戶存取或轉帳授權。條件與意願分開，不能把不能負擔解讀成不夠愛。

## 結果規則候選

1. **先看本人範圍／條件**：03與10為現實條件，06為本人願意集中處理的範圍。單獨忠實呈現，不判相同／不同、能力高低或要求折衷。本人這次不參加或不集中不被分攤偏好覆蓋。
2. **偏好與流程**：05／09／12只在主要選項時說同題選擇相同或不同；04／11只讀想先確認什麼。相同原則不證明負擔可行、理由相同或覺得公平，不排名「最好」安排。
3. **兩組雙向配對**：01期待對另一方02自述、08期待對另一方07自述；A對B、B對A獨立，只按同組語意ID比較。任一其他、依情況改變、未確定、沒經歷、不適用或未分享就advice:null，不把兩個other判相同。
4. **提案不是金融操作**：8則給提供回應者的原創提案只幫確認資訊與意願，不要求開戶、合併、付款、借款、帳務公開或提供登入。選答與沉默都不能代替當次付款／使用帳戶許可。
5. **不足與版本**：沒有可比較資料就明說不足，不推定低投入。新條件另開一輪，舊快照不改。不得用核心價值相近度、日常三觀接受集合或溝通分析直接代替本主題規則。

候選附9種虛構規則審閱例子，例如「兩人偏好平分，但本人這次不參加」「目前不願集中」「沒有共同花費經歷」「方向不同」「新安排不是付款許可」。另一方未收集的偏好不捏造；這些是設計案例，尚非運行分析測試或使用者答案。

排查順序：

- 題目難答：先請審閱者改述「你／對方」，查是否假定同居／共同帳戶，再分辨沒有經歷、選項重疊或多個都優先；不要用朋友試讀好評當量表驗證。
- 結果說「想要但做不到＝不合」：先查`perspective`、`constraintQuestionIds`與`boundaryQuestionIds`。條件與本人範圍不得進crossPairs／交集／相似度，查拒絕選項是否被偏好覆蓋。
- 費用確認反向：核對wanted／provided題號，01對02、08對07，A期待對B自述；不比相同題答案就宣稱對方做到了。
- 描述超出答案：查原選項、source.readScope／limitations，不用分攤類別推財務焦慮、收入、信用、人格或關係成敗。
- 找不到網站入口：目前仍planned；安全指令 `rg -n 'money-life|一起生活的選擇' src/content/quizzes.ts docs README.md`。候選JSON不被registry匯入，不需改D1／重部署來讓草稿出現。
