## 作答方式

直接回答目前想法。「你」是本人，「對方」是這輪一起回答的人。行為題只回想最近一個月與這輪對方的經歷，沒遇過可明示沒有經歷。主要選項為單選最接近／最優先的一項；其他、依情況改變、未確定、不適用與暫不分享均可回答。界線題是現在願意的範圍，不是對方可直接採取行動的許可；有需要時仍確認當次同意。候選接入提案為雙方完成後看到願意分享的選項及特殊狀態；暫不分享取代原選項，不要求補寫私人細節。

每題另有以下出口（單選，不要求補寫內容）：

- 其他方式比較接近我（`other`）
- 會依情況改變，目前沒有固定方式（`varies`）
- 目前還沒想清楚（`uncertain`）
- 這題目前不適用（`not-applicable`）
- 這題我暫不分享（`not-shared`）

行為題另有「最近一個月，和對方沒有遇過這個情況」。其他／情境變動不是中間分數，未分享不表示秘密或不信任。

## 陪伴與獨處

分清想怎麼一起相處、獨處時想保留什麼，以及如何回應獨處需要。

### 01．如果兩人都願意一起待一段時間，你目前最想怎麼相處？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 留一段時間專心聊彼此的近況（`talk`）
2. 一起做一件雙方想做的事（`shared-activity`）
3. 待在同一個地方，各做自己的事（`parallel`）
4. 安靜待在一起，不一定聊天或做事（`quiet-company`）

類型：preference；ID：`space-together`。

依據：patrick-2007。連結需求的概念延伸，不把一起做同一件事當作唯一陪伴，也不測需求滿足。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：哪種相處讓你感到有人陪著？哪些場合會不同？

### 02．如果你想留一段時間自己待著，你目前最想先保留什麼？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 不被打擾地休息（`rest`）
2. 投入自己的興趣或想做的事（`interest`）
3. 整理自己的想法或感受（`reflect`）
4. 暫時不用回應或安排任何事（`unplanned`）

類型：preference；ID：`space-alone-focus`。

依據：nguyen-2018。研究區分獨處情境與動機；本題只問目前用途偏好，不能推定孤單、情緒問題或最佳時長。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：這段時間對你有什麼作用？你願意讓對方知道哪一部分？

### 03．當你向對方說想自己待一下時，你目前希望對方先怎麼回應？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 簡短表示知道了，再留空間給我（`acknowledge`）
2. 先問我是否希望之後再聯絡（`ask-contact`）
3. 先和我確認眼前必要事項怎麼處理（`necessary-matters`）
4. 暫時不用回覆，先讓我安靜一下（`no-immediate-reply`）

類型：partner-expectation；ID：`space-alone-want`。

依據：patrick-2007、nguyen-2018。自主與獨處概念的回應情境延伸，不要求報備理由或承諾固定恢復聯絡期限。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：你希望的這個回應，是讓你知道什麼？

### 04．最近一個月，當對方明確說想自己待一下時，你通常先怎麼回應？

只回想最近一個月與這輪對方的經歷，選最接近通常第一步的一項。沒遇過可選沒有經歷，不用過去關係代答。

1. 簡短表示知道了，再留空間給對方（`acknowledge`）
2. 先問對方是否希望之後再聯絡（`ask-contact`）
3. 先和對方確認眼前必要事項怎麼處理（`necessary-matters`）
4. 暫時不回覆，先讓對方安靜一下（`no-immediate-reply`）

類型：self-behavior；ID：`space-alone-do`。

依據：patrick-2007、nguyen-2018。與上一題比較回應類別，不測是否真的尊重界線或是否感到被照顧。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：什麼情況下你會用這個回應？對方當時可能需要什麼，仍要由對方說明。

## 資訊分享

由資訊與影像的本人表達願意分享的範圍；做法自述不等於取得許可。

### 05．如果對方想用你的手機做一件事，你目前願意怎麼安排？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 每次先說用途，問我當次是否願意（`ask-each`）
2. 先告訴我想做什麼，由我自己操作（`owner-operates`）
3. 只在我已明確答應的用途與期限內使用；變更再問（`agreed-purpose`）
4. 目前不願讓對方操作我的手機（`no-access`）

類型：owner-boundary；ID：`space-phone-boundary`。本人界線單獨顯示，不作同類／差異或折衷。

依據：dragiewicz-2026、doerfler-2024。裝置存取與使用範圍分開。此題表達本人目前界線，不授予產品或對方實際存取權。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：如果願意借用，哪些用途可以、哪些內容仍不想被看見？也可以保留不借用。

界線處理：未明示的用途不是許可，當次同意可比本輪範圍更窄；不要求分享密碼或降低安全設定。

### 06．最近一個月，當你想用對方的手機做一件事時，你通常先怎麼處理？

只回想最近一個月與這輪對方的經歷，選最接近通常第一步的一項。沒遇過可選沒有經歷，不用過去關係代答。

1. 先說用途，問對方當次是否願意（`ask-purpose`）
2. 按先前已明確答應的用途與期限使用（`prior-agreement`）
3. 請對方自己操作，讓我知道需要的資訊（`owner-operates`）
4. 不另外確認就使用（`without-checking`）

類型：self-behavior；ID：`space-phone-do`。

依據：dragiewicz-2026、doerfler-2024。做法自述只保留情境，不與對方界線用相同ID／順序比契合；不先確認不是產品建議。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：這個做法依據的是哪個明確約定？如果沒有約定，先保留不用對方手機的方式。

### 07．兩人私下聊到與你有關的私人內容，對方對外提起前，你目前希望怎麼處理？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 每次先問我是否願意、可以說到哪裡（`ask-each`）
2. 只依已明確約定的內容與對象分享；變更再問（`agreed-audience`）
3. 先讓我自己決定是否對外說（`self-share`）
4. 目前不願讓對方把這些內容對外提起（`no-forward`）

類型：owner-boundary；ID：`space-private-story`。本人界線單獨顯示，不作同類／差異或折衷。

依據：本站自編，沒有本題直接研究。從裝置隱私延伸到日常內容需另有證據，這題明示自編；不把一般隱私安排延伸為限制本人求助。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：哪種內容你願意自己說，哪種希望保留？不需要提供私人故事。

界線處理：題目針對一般對外轉述私人內容；尋求支持不需取得對方批准，提案不限制求助或要求交出他人可識別細節。

### 08．如果對方想公開一張包含你的兩人合照，你目前願意怎麼安排？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 每張照片公開前都先讓我看，再問我是否願意（`ask-each-photo`）
2. 只在我已明確答應的照片、對象與平台範圍公開（`agreed-scope`）
3. 先只私下傳給我，這輪先不談公開（`share-to-me`）
4. 目前不願公開包含我的兩人合照（`no-public-photo`）

類型：owner-boundary；ID：`space-photo-boundary`。本人界線單獨顯示，不作同類／差異或折衷。

依據：本站自編，沒有本題直接研究。照片／身分可見性為本站界線情境，不借裝置研究驗證本題，也不預設關係已公開。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：如果願意公開，照片、標記和看得到的人是否都符合你目前願意的範圍？

界線處理：沒有明確同意先不公開；不能用先前貼過照片推定新照片、標記或其他平台已獲同意。

## 人際與安排

保留各自朋友與原有安排，了解聯絡期待及界線如何更新。

### 09．如果對方和朋友另有安排，而且不影響原本共同約定，你目前最希望收到哪種聯絡？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 不需要固定告知（`no-fixed-update`）
2. 讓我知道什麼時候不方便聯絡就好（`availability`）
3. 自願分享大致活動就好（`general-plan`）
4. 一起確認下次方便聯絡的時機（`next-contact`）

類型：partner-expectation；ID：`space-friends-want`。

依據：patrick-2007。自主概念的聯絡期待延伸，不證明最佳報備規則，不按朋友性別／性向判斷；期待不是控制他人行程的授權。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：這個聯絡對你有什麼作用？你能接受哪些資訊保留給對方自己？

### 11．你已經有自己的安排，又收到對方臨時的相處邀請時，你目前希望對方先怎麼回應你的安排？

回答目前想法。若多項符合，先選在這個情境最優先的一項；選答不等於承諾，也不能代替當次同意。

1. 接受我保留原安排（`keep-plan`）
2. 問我是否願意調整，讓我自己決定（`ask-adjustment`）
3. 一起找不需要更動原安排的其他時間（`another-time`）
4. 先讓我想一想，之後由我答覆（`time-to-think`）

類型：owner-boundary；ID：`space-existing-plan`。本人界線單獨顯示，不作同類／差異或折衷。

依據：patrick-2007。自主選擇的情境延伸；不把拒絕臨時邀請算低投入，不預设必須調整或證明重視。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

界線處理：邀請可以被拒絕，暫不答覆不是同意；另約時間須雙方願意，不要求立即給替代安排。

1. 現在願意的範圍是什麼（`new-scope`）

類型：process-preference；ID：`space-update-boundary`。

依據：本站自編，沒有本題直接研究。界線更新流程為本站提案，不用新一輪答案改寫舊回合，也不把過去同意當成永久同意。 題幹、分類與提案為本站原創，不是原工具翻譯，理解／測量／效果未驗證。

一起確認：你願意現在說清楚的是哪一部分？未決定的部分能否先保留？

## 結果規則候選

先讀各自現在願意的範圍，再看偏好、做法與回應；不是測誰界線較鬆或較緊。

owner-boundary單獨忠實顯示，沒有同類／差異／相似度或建議折衷；本人拒絕、不願現在答覆、未分享或未決定不因另一方要求而改成允許。其他選項也不能把本輪回答當成當次授權；第三方資訊及求助出口分開。

只在雙方主要選項時說同題選擇相同或不同；不給大小、優劣、最佳獨處時長或推測孤單動機。特殊狀態只保留情境。

A期待對B做法、B期待對A做法，各方向獨立。僅兩邊都是主要選項才比同組語意ID；相同不證明已尊重界線或期待已被滿足，不同不代表衝突。任一特殊狀態advice:null。給提供回應者的提案由期待選項選取，須自願且不得越過本人界線。

### 說想獨處時，希望與自述回應

期待題 `space-alone-want` 對另一方做法題 `space-alone-do`，雙向獨立。

| 期待方選項 | 給提供回應者的可選提案 |
| --- | --- |
| 簡短表示知道了，再留空間給我 | 可以簡短回應已聽到這個需要，再確認是否有必須處理的事；不要求說完原因才給空間。 |
| 先問我是否希望之後再聯絡 | 可以先問是否希望之後再聯絡；不想現在決定，也能保留。 |
| 先和我確認眼前必要事項怎麼處理 | 可以只確認眼前共同責任怎麼處理，不要求用說明全部行程換取獨處。 |
| 暫時不用回覆，先讓我安靜一下 | 可以確認雙方如何辨認這段不立即回覆的需要，不把安靜直接解讀成不在乎。 |

期待方先說這個回應對自己的意思；提供方再說實際條件，確認是否願意採用。

### 各自與朋友相處時的聯絡

期待題 `space-friends-want` 對另一方做法題 `space-friends-do`，雙向獨立。

| 期待方選項 | 給提供回應者的可選提案 |
| --- | --- |
| 不需要固定告知 | 可以確認原本共同約定是否仍有效；各自安排不需要額外提供朋友或位置資料。 |
| 讓我知道什麼時候不方便聯絡就好 | 若雙方願意，可只說不方便聯絡的時段，不要求固定秒回或提供定位。 |
| 自願分享大致活動就好 | 可以分享自己願意說的大致活動，明示哪些細節想保留；不追問他人的私人資訊。 |
| 一起確認下次方便聯絡的時機 | 若雙方願意，可確認下一次方便聯絡的時機；臨時不能聯絡時保留調整空間。 |

先說你想得到的是什麼，再確認另一方願意與做得到的範圍；不把期待當規定。
