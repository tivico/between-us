# 好好說，也好好聽：研究與內容藍圖

更新／查核日期：2026-10-12。藍圖版本 `0.1.0`；狀態：研究與設計提案，尚未形成完整題庫或接入雙人回合。使用者已選定這個主題，要求直接詢問自己的做法與期待，不用「這個人」的人物描述。網站仍為 `0.10.0`，`communication` 仍為 `planned`。

## 已確認的作答方式

用「你」指作答者、「對方」指這輪一起回答的人。一題只問一個重點，直接問本人可回想的經驗或目前期待，例如「你通常怎麼開口？」、「你希望對方怎麼回應？」。不要求先想像另一個人物，再判斷自己和人物多像；這是使用者回饋的產品選擇，不是證明這種題型對所有人測量更準。

- 行為題：暫以「最近一個月，與這輪對方……」為回想範圍，再問通常做法。時間窗是本站提案，需試答確認能否回想足夠情境。
- 期待題：明示「如果發生……，你目前希望……」，回答期望，不視為已發生的事或要求對方履約。
- 沒有相關經歷：保留「最近沒有遇到這個情況」；交往前也能用，不把對過去伴侶的答案當成本輪互動。
- 尚未想清楚、不適用、暫不分享分開。未答不能當零，特殊狀態不能當兩人共同偏好。
- 不混問「怎麼做、想要什麼、重不重要、對方有沒有做到」。若需要以上資料，分別設題。
- 這項偏好適用於本次溝通主題及後續新題設計；既有 PVQ-RR 57 題與舊回合維持原工具與快照。直接改寫既有量表的施測形式需另記版本，不能沿用原版驗證主張。

## 產品目的與分工

讓兩人理解「我怎麼提出問題、希望收到什麼回應、需要暫停時怎麼表達、之後如何回來處理」。目標是找出值得確認的互動期待與可討論的安排，不以題目判定誰比較會溝通、誰有問題或關係是否成功。

既有 `know-repair` 四題問答聚焦表達、暫停、道歉與回饋，是短聊天入口；本主題要串起完整討論歷程，增加本人做法與對方期待的雙向配對，避免只把原四題換字重複發布。遠距已處理日常支持，本主題的回應題聚焦兩人有不同意見的情境。

| 編輯段落 | 要了解什麼 | 結果應區分什麼 |
| --- | --- | --- |
| 提出需求 | 什麼時機、怎麼開口、希望如何被提出 | 本人通常做法與另一方希望收到的方式 |
| 聽懂與回應 | 先聽感受、澄清意思、表達不同意見 | 自述提供的回應與對方期待，不推定實際已被理解 |
| 暫停與再談 | 情緒升高時如何表達需要、如何重新開啟 | 暫停需求、可行安排與返回討論的期待 |
| 修復與追蹤 | 誤會後希望如何確認理解、處理未完成事項 | 希望得到的修復與自述做法，不推定已原諒或已解決 |

這四段是產品內容分類，不是經驗證的四因子量表。題數、完成時間、完整選項與數字計分未定；不預設婚姻、同居、性別角色或生育。

## 既有工具比較與設計建議

| 候選工具 | 符合目的的部分 | 本輪處理與待核對項目 |
| --- | --- | --- |
| CPQ：Communication Patterns Questionnaire（溝通模式問卷） | 最接近分歧討論歷程，原本就是本人自述，不需人物相似程度題型 | 優先核對完整工具／繁體譯本。論文提到免費副本，不等於公開網站、翻譯與改寫的授權均已確認；未套用原題、九段量尺或修訂分數 |
| DCI：Dyadic Coping Inventory（雙人共同因應問卷） | 本人與對方如何表達壓力、互相支持，有中文驗證論文 | 偏壓力因應，不能獨自覆蓋衝突暫停／修復；保留為補充比較，不使用本輪尚未取得的題本與分數 |
| PRI：Perceived Responsiveness–Insensitivity（感受到的回應性／不敏感量表） | 了解本人是否感到被聽見、理解與關心，和「回覆速度」不同 | 已讀[作者手冊](https://sas.rochester.edu/psy/sites/reis/wp-content/uploads/2025/10/PRI-Handout.pdf)前兩頁；非臨床／非研究用途需作者書面許可，翻譯另聯絡。原工具及譯本未獲許可，不複製題目或套分數；既有遠距稿有原研究資料 |

**提案：先以研究支持的原創情境題製作可審閱候選稿，同時保留 CPQ 的工具核對路徑。** 理由是產品要比較做法與期待，候選量表主要測互動或感受，不能直接替代雙人期待配對。這仍是設計建議，使用者目前確認的是主題與直問題型，尚未選定原創／量表比例或計分方案。若最後採 CPQ，保持核定原題、選項與分數另成區塊；不把自編題混入量表總分。

## 八個直問示例（本站原創、非完整題庫）

以下用來核對方向與主詞；尚無正式選項、題數或分析規則，不冒充 CPQ／DCI／PRI 翻譯。行為題都限定本輪對方，尚未遇過可明確回答沒有經歷。

| 暫用 ID | 類型／配對 | 題幹 | 依據與設計延伸 |
| --- | --- | --- | --- |
| `comm-open-do` | 本人做法 | 最近一個月，當你對兩人的安排有不同想法時，你通常怎麼向對方開口？ | CPQ 的問題發生階段；具體安排與單選分類為本站設計 |
| `comm-open-want` | 希望收到的方式 | 如果對方對兩人的安排有不同想法，你希望對方怎麼向你開口？ | 與上一題語意配對；期待題為本站延伸，不計 CPQ 分數 |
| `comm-listen-do` | 本人做法 | 最近一個月，當對方說出和你不同的想法時，你通常先怎麼回應？ | CPQ 討論階段、Pagani 回應概念的情境延伸；不預設哪種回應較好 |
| `comm-listen-want` | 希望收到的方式 | 當你說出和對方不同的想法時，你希望對方先怎麼回應？ | 與上一題配對；本人期待不能證明實際曾被理解或忽略 |
| `comm-pause-do` | 本人做法 | 最近一個月，當討論讓你情緒升高、想先停一下時，你通常怎麼讓對方知道？ | Holley 互動概念與 Salvatore 恢復歷程的本站延伸；不把暫停直接判成逃避 |
| `comm-pause-want` | 希望收到的方式 | 如果對方需要先停一下，你希望對方怎麼讓你知道？ | 與上一題配對；只問通知，何時再談需另外設題 |
| `comm-return-do` | 本人做法 | 最近一個月，一次討論暫停後，你通常怎麼重新開啟還沒談完的事？ | Salvatore 討論後歷程的本站延伸；不是原觀察編碼或依附測量 |
| `comm-return-want` | 希望收到的方式 | 一次討論暫停後，你希望對方怎麼和你重新開啟還沒談完的事？ | 與上一題配對；重啟、道歉、確認理解與追蹤落實分開，正式修復題待寫 |

例如 `comm-pause-want` 可試寫選項：「先說需要整理一下」、「先讓我知道仍願意繼續談」、「先說現在無法繼續的原因」、「先問我們要怎麼安排這次暫停」。這些可能同時符合，必須試答確認是否適合問「最優先希望聽到哪一項」，或改為分題；不能為了湊四選項就把它們假設為互斥。正式題庫還須補通知以外的返回安排與修復內容。

## 結果閱讀層提案

先提供可查答案的理解摘要，再給具體情境與討論提案，最後展開逐題答案與研究說明。這是產品設計，沒有本產品效果證據。

1. 做法配期待：A 的 `*-want` 比 B 的 `*-do`，B 的 `*-want` 比 A 的 `*-do`；同方向配對，不能比較兩人的通知習慣就宣稱期待已被滿足。
2. 兩人的期待可並排閱讀；相同選項只代表本題選擇相同，不代表理由相同或實際相處沒有問題。
3. 原創名目選項（不同做法的分類）沒有自然大小，不能以選項 ID／順序換成分數。首稿提案不提供契合百分比、優劣排序或溝通人格標籤。
4. 任何一方沒有經歷／尚未想清楚／不適用／暫不分享時，該配對只保留可分享的狀態，不生成共同點、差異或針對答案的提案。
5. 具體聊法先說「可能可以確認……」，並列觸發題／實際選項；不寫「你總是逃避」、「對方不在乎」或「你們容易吵架」。暫停與安全界線不要求單方讓步，不把立即回來談當義務。

示意：一方希望先聽到「仍願意繼續談」，另一方自述先說「需要整理」。結果可邀請雙方確認「這兩句話對你各代表什麼？下次想暫停時，願不願意把兩個訊息一起說清楚？」。這是假設例子，並非使用者答案，也不是研究已證實有效的固定話術。

## 實際工作流程、維護與除錯

本輪只有文件，沒有 Request／Data Flow 或私人答案讀寫。內容工作順序為：研究／工具核對 → 記錄可支持與不能支持的主張 → 直接題幹與選項候選 → 逐題審閱與自願試答 → 完整結果規則 → 接入與工程驗證。測量效度與產品效果另外驗證。

未來核定後才走：`src/content/quizzes.ts` 註冊 `communication` → 建立回合固定題庫／規則快照 → Node／D1 保存兩人獨立答案 → 雙方授權並提交後生成結果 → 前端顯示摘要／逐題依據。未來實作須同步兩種 store（資料保存層），沿用既有分享與特殊狀態邊界；此段是預定流程，尚未發生。

排查順序：

1. 問題難回答：請試答者改述題意，先查「你／對方」是否清楚、時間窗是否有經歷、是否混問做法與期待，再查選項是否重疊；不直接歸因使用者不熟心理學。
2. 結果看似對不上：先查候選題 ID 與配對方向，再查行為／期待／條件是否被混在一起；相同選項不自動視為滿足。
3. 聲稱已驗證或來源不符：查本文件來源表的已讀範圍、工具版本／題本／許可；找不到對應證據就收回主張，不用論文數量代替驗證。
4. 文件和畫面不同：目前畫面仍應為籌備中。可安全執行 `rg -n 'communication|好好說' src/content/quizzes.ts docs README.md` 確認登錄狀態；本文件的候選題不會自動載入網站。

日後修改範例：若想增加「何時再談」，新增獨立的安排／期待題，先確認兩題說的是同一情境，不把返回時間塞入 `comm-pause-do` 造成一題問兩件事。補上來源／自編範圍、特殊狀態與配對規則，更新候選版並試答。正式工具接入後改題／選項／提案升工具內容版；改算法另增分析版本，保留舊規則與回合快照。
