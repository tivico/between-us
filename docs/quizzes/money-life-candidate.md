## 作答方式

直接回答你目前的想法。「對方」是這輪一起回答的人。最近做法只回想一個月內與本輪對方的經歷，沒有共同花費／沒遇過就明示沒有經歷，不用過去關係代答。單選最接近／最先／最優先的一項，可選其他、依情況改變、未確定、不適用或暫不分享。不填收入、資產、負債、帳戶、金額或私人財務文件。選答不是付款承諾、轉帳授權或同意集中資金；想要的安排也不表示現在做得到。候選接入提案為雙方完成後看可分享選項；暫不分享取代原選項，只顯示未分享，不要求理由。

每題另有以下出口：

- 其他方式比較接近我（`other`）
- 會依情況改變，目前沒有固定方式（`varies`）
- 目前還沒想清楚（`uncertain`）
- 這題目前不適用（`not-applicable`）
- 這題我暫不分享（`not-shared`）

兩題最近做法另有「最近一個月，和對方沒有遇過這個情況」。未答不補值，暫不分享不推定不信任；期待、條件與界線分開。

## 消費與儲蓄

了解提出非必要活動時先談什麼、超出本人負擔時怎麼處理，以及共同預留的討論起點。

### 01．如果對方想安排一項需要兩人出錢的非必要活動，你目前最希望先知道什麼？

回答目前想法。若多項符合，先選這個情境最優先的一項；不用提供金額、收入、資產或帳戶。選答不等於答應出錢，也不是付款或使用帳戶的許可。

1. 對方為什麼想做這個活動（`meaning`）
2. 這個活動大概包含哪些費用（`cost-scope`）
3. 它對原本共同支出可能有什麼影響（`shared-impact`）
4. 有哪些不同規模或負擔的安排可以選（`alternatives`）

類型：partner-expectation；ID：`money-proposal-want`。

依據：peetz-2023。從花費優先順序、共同決策與責任的議題延伸，不把選擇某種資訊當節儉或浪費人格。 題幹、選項分類及提案皆為本站原創，不是原量表翻譯；理解、測量與效果未驗證。

一起確認：你最想先知道這件事，是因為什麼？哪些資訊不必立刻決定？

### 03．如果一項共同活動超出你目前願意且能負擔的範圍，你目前比較希望怎麼處理？

回答目前想法。若多項符合，先選這個情境最優先的一項；不用提供金額、收入、資產或帳戶。選答不等於答應出錢，也不是付款或使用帳戶的許可。

1. 改成較小規模的活動，再確認我是否能參加（`smaller-plan`）
2. 先延後，之後有合適條件再重新討論（`later`）
3. 各自選能負擔的安排，不要求參加同一項（`separate-options`）
4. 這次先不參加，也先不安排替代活動（`not-participating`）

類型：constraint；ID：`money-over-capacity`。

依據：本站自編，沒有本題直接研究。本人負擔與參與條件為本站情境，不問多少錢或推定經濟地位；條件單獨讀，不列共同點／差異。 題幹、選項分類及提案皆為本站原創，不是原量表翻譯；理解、測量與效果未驗證。

一起確認：你願意說明的限制是什麼？哪些部分可以先保留，不必提出替代安排？

處理原則：本人不參加的選擇不能被對方偏好覆蓋，不要求更多出錢、借款或提供財務證明來證明投入。

### 04．如果兩人想為一個共同未來計畫預留錢，你目前最希望先確認什麼？

回答目前想法。若多項符合，先選這個情境最優先的一項；不用提供金額、收入、資產或帳戶。選答不等於答應出錢，也不是付款或使用帳戶的許可。

3. 各自目前願意且能負擔的範圍（`affordable-scope`）

一起確認：先確認這件事，會幫你決定哪一部分？還有哪些事現在不知道？

## 共同支出

### 05．如果兩人已同意一起支付某項共同花費，你目前比較希望用哪個原則分配？

回答目前想法。若多項符合，先選這個情境最優先的一項；不用提供金額、收入、資產或帳戶。選答不等於答應出錢，也不是付款或使用帳戶的許可。

1. 各自支付相同金額（`equal-amount`）
2. 先各說願意且能負擔的範圍，再定這一次分配（`capacity-ranges`）
3. 依各自實際使用或受益的部分分配（`use-share`）
4. 先把費用拆成不同項目，再各自選願意負擔的部分（`agreed-items`）

### 06．一起支付共同花費時，你目前願意讓哪些金錢集中處理？

1. 目前都不集中，想先各自處理（`none-separate`）
2. 只為這一次已答應的共同安排留一筆，其他各自處理（`this-plan-only`）

一起確認：如果願意集中，用途、可見範圍與停止／調整方式是否都說清楚？也可以保留各自處理。

處理原則：本人目前不願集中或未決定時，沒有可執行的合併許可。不要求帳戶、密碼、登入、轉帳、財務文件或全額透明；過去安排不自動延用為當次同意。

## 結果規則候選

constraint與owner-boundary單獨忠實呈現，不判共同／不同或能力高低，不讓偏好覆蓋本人不參加／不願集中。條件不是價值優劣，界線不是帳戶／付款許可。

主要選項可描述同題選擇相同或不同，不給大小、優劣、契合或公平分數；相同不表示理由相同／已能負擔。特殊狀態只保留情境。

只讀想先確認什麼，不推定已同意、已預留款項或已出現衝突；不知道／沒經歷／不適用不視為零投入。

A期待對B自述、B期待對A自述，兩方向獨立。僅雙邊為主要選項才按同組語意ID比同類／不同；相同不等於已確認費用、付款或參加，不同不推定衝突。任一特殊狀態advice:null，不能把兩人都其他判同類。條件與本人界線不得放進crossPairs。

### 提出非必要活動時，先說什麼

期待題 `money-proposal-want` 對另一方最近做法題 `money-proposal-do`，雙向獨立。

| 期待方選項 | 給提供回應者的可選提案 |
| --- | --- |
| 對方為什麼想做這個活動 | 可以先說為什麼想做這件事，再由另一方確認是否也有興趣；提出理由不是要求參加。 |
| 這個活動大概包含哪些費用 | 可以先列有哪些費用需要確認，不必現在提供收入或資產；不清楚的部分先保留。 |
| 它對原本共同支出可能有什麼影響 | 可以先確認是否會影響已說好的共同支出，區分已知條件與尚未知道的費用。 |
| 有哪些不同規模或負擔的安排可以選 | 若雙方願意，可各提一種不同規模的安排；任何人仍可選擇這次不參加。 |

期待方先說最想得到的資訊，提出方再說目前知道多少；先確認參與意願，再決定下一步。

### 共同費用怎麼確認

期待題 `money-confirm-want` 對另一方最近做法題 `money-confirm-do`，雙向獨立。

| 期待方選項 | 給提供回應者的可選提案 |
| --- | --- |
| 把用途與各自負擔的部分寫清楚，再彼此確認 | 若雙方願意，可以只記這次用途與各自願意負擔的部分；不要求公開完整個人帳務。 |
| 口頭逐項確認，讓雙方補充或修正 | 可以逐項輪流確認理解，任何未答應的部分先保留，不把沉默當同意。 |
| 先看共同清單，再確認這次有沒有改動 | 可以先看雙方已願意使用的共同清單，確認這次變動；原清單不是永久付款許可。 |
| 等主要資訊更清楚，再決定這次是否參加 | 可以先列還不知道的事項，再確認是否想另約時間；暫緩決定不等於不願投入。 |

## 必須審閱的規則例子（全為虛構）

| 情境 | 示例 | 應有結果 |
| --- | --- | --- |
| 偏好相同但本人不能負擔 | A及B split-principle=equal-amount；A over-capacity=not-participating | 分攤偏好相同與A這次不參加分開呈現，不推定可執行、不要求A出錢或證明投入。 |
| 不願集中資金 | A pooling-boundary=none-separate；未收集B希望全面合併的資料 | 忠實顯示A目前願意範圍，不捏造B答案，不給合併更有愛／不透明的評語。 |
| 兩方向不同 | A proposal-want=cost-scope、B proposal-do=meaning；B proposal-want=meaning、A proposal-do=meaning | A期待←B自述為不同；B期待←A自述為同類，不能合成兩人已一致。 |
| 沒有共同費用經歷 | B confirm-do=not-experienced | 相關方向只保留沒有經歷、advice:null；不猜未來，不填零，另一方向獨立。 |
| 兩人都其他 | A proposal-want=other、B proposal-do=other | 情境，不判同類、不給該方向提案。 |
| 收入／時間改變 | A plan-change=current-scope，沒有具體金額或變動原因 | 只說A希望先確認現在範圍，不推定失業、貧窮、焦慮或分手風險。 |
| 新安排不是付款許可 | 兩人 pooling-boundary=this-plan-only或confirm-want=written-scope | 只是本輪回答；沒有轉帳、開戶、合約或提供憑證的操作與授權。 |
| 拒絕與未分享 | A pooling-boundary=not-shared或discuss-first | 只顯示目前狀態，不追問資產／秘密，未知範圍不能當已允許集中。 |
| 舊回合與新條件 | 新一輪本人條件或意願不同於上次 | 新輪只讀當前回答，舊snapshot與分數不追改；過去安排不等於永久授權。 |
