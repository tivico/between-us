# 更認識你：32 題選擇題候選稿

更新日期：2026-10-08。候選版本：`0.1.0`。內容方向已獲使用者同意；本稿尚未逐題驗收、接入程式或發布。

## 定位與範圍

兩人各自選擇最接近自己的答案，揭曉後聊聊原因，認識日常、支持需求、界線與關係期待。適用交往前與交往中，不預設已婚、同居、排他關係或任何性別／性向；生育不在本版範圍。

使用者提供的開放式問答清單是內容起點。八面向是編輯分類，不是八種人格或經驗證量表；32 題與討論提示均為本站自編。本稿補充核心價值探索，不併入 PVQ-RR 的 57 題或相近度計算。

## 共用作答與分享規則（待接入）

引導：「選最接近你目前想法的一項。可能有好幾項符合，先選在這個情境下最優先的一項；沒有標準答案，回答也不等於答應對方。」

每題 A–D 是具體選擇，另共用以下出口，不要求補寫文字：

- 「其他較接近我的做法」：已有想法，但 A–D 沒涵蓋。
- 「沒有固定偏好，會依情境改變」：知道自己的想法隨條件而變。
- 「尚未想清楚」：目前尚無明確答案。
- 題目標有「尚未經歷」時另提供該選項；假設期待題仍能回答，不強迫用未經歷作答。
- 「這題目前不適用」：情境不適合本人，不要求原因。

另提供「暫不分享這題」操作，與答案分開：清除本題已填選項，結果只顯示「未分享」，不揭露先前選擇或要求原因；提交前明說對方會看見此狀態。實作必須由後端保護，不能只在前端隱藏。

未答、尚未想清楚、尚未經歷、不適用、暫不分享是不同狀態。本題組預計每題已選答案或明確暫不分享才能提交，未答仍不能提交；不套用核心價值的數值計分、不填零。現有 API 尚不支援本稿的暫不分享契約。

討論提示在揭曉後提供，不必在網頁輸入或上傳故事。私密題組可以整組不選，已選題組內仍可暫不分享。未分享、不適用、未經歷、尚未想清楚不列為共同偏好或差異；「其他」或「依情境」相同也不能推論具體偏好相同。

## 01–04｜日常與相處節奏

### 01 `know-daily-free-day`

**以最近兩週的生活狀況來說，如果多出一天不用工作或處理既定責任的空檔，你最想先安排什麼？**

- A．待在家休息，做點自己的事
- B．出門走走，換個環境
- C．約重要的人一起相處
- D．投入一件一直想做的興趣或計畫

討論提示：如果這天我們一起過，有沒有哪一段時間你想留給自己？

### 02 `know-daily-plan`

**安排一次兩人的出遊，你目前比較喜歡哪種方式？**

- A．事先排好主要行程與時間
- B．先決定一兩個必去的地方，其他當天再說
- C．只約好出發時間與集合地點，到了再安排
- D．先列出幾種備案，依當天狀況挑選

討論提示：哪些安排你希望提前知道，哪些可以臨時決定？

### 03 `know-daily-tired`

**最近兩週，當你很累但還在和人相處時，最常出現哪種反應？**

- A．話變少，反應也比較慢
- B．比較容易不耐煩
- C．想找熟悉的人說話或待在一起
- D．表面上照常互動，別人不容易看出來

另提供：尚未經歷（最近兩週沒有這個情境）。

討論提示：對方怎麼確認你是不是累了，會讓你比較自在？

### 04 `know-daily-social`

**約會途中臨時遇到一群熟人，對方想加入他們的活動，你比較希望怎麼安排？**

- A．維持原本兩人的安排
- B．短暫打招呼，再繼續原本安排
- C．確認雙方都願意後，一起加入
- D．對方可以加入，我自行安排接下來的時間

討論提示：改變原本安排前，你最希望先確認什麼？

## 05–08｜思考與壓力

**面對一個重要、但不需要立刻決定的個人選擇，你通常先做什麼？**

- A．蒐集資料，比較各種可能
- B．先確認自己最想要哪個方向
- C．找信任的人聊聊
- D．先做一個能回頭的小嘗試

討論提示：對方在哪個階段參與，最能幫到你？

### 06 `know-thinking-pressure`

- A．列出待辦，分出先後順序
- B．先完成一件能處理的小事
- C．找人說說目前的狀況
- D．先停一下，恢復精神再處理

另提供：尚未經歷（最近一個月沒有這個情境）。

討論提示：有哪些行為看起來像拖延，其實是你在整理自己？

### 07 `know-thinking-advice`

**對方想對你正在煩惱的事提出建議，你希望對方怎麼開始？**

- A．先問我想不想聽建議
- B．先聽完整件事，再提出想法
- C．直接說一個具體可行的做法
- D．先一起釐清問題，不急著給做法

討論提示：如果建議暫時不適合你，你希望怎麼回應彼此？

### 08 `know-thinking-change`

**一項你很期待的共同安排臨時取消時，你通常最先想做什麼？**

- A．先了解取消的原因
- B．立刻找替代安排
- C．先說出自己的失望
- D．留一點時間消化，再討論後續

討論提示：哪一種說明或後續安排，對你最有幫助？

## 09–12｜關心與親近

### 09 `know-care-support`

**壓力很大時，你通常最希望對方先怎麼做？**

- A．聽我說，先不用給建議
- B．陪我整理問題與下一步
- C．陪我做點別的，暫時轉換心情
- D．讓我獨處，約好晚點再聯絡

討論提示：你通常會怎麼讓對方知道，你現在需要這種支持？

### 10 `know-care-appreciation`

**對方想表達欣賞時，你目前最希望被注意到哪一部分？**

- A．我為事情付出的努力
- B．我處理事情的能力
- C．我待人或思考的方式
- D．我的外表或個人風格

討論提示：怎樣的稱讚會讓你感到具體，而不是客套？

### 11 `know-care-affection`

**在雙方都願意的前提下，見面時你目前最喜歡怎麼表達親近？**

- A．牽手或擁抱等肢體接觸
- B．說出喜歡、在乎或想念
- C．專心一起做一件事
- D．保留身體距離，用陪伴表達

討論提示：當天不想接觸時，你希望怎麼表達，讓彼此都自在？

### 12 `know-care-surprise`

**對方想為你安排一個特別的日子，你比較希望哪種方式？**

- A．一起討論內容與細節
- B．先確認時間與預算，內容保留驚喜
- C．從我提出的幾個選擇中安排
- D．維持平常相處，不特別安排活動

討論提示：有哪些內容即使是驚喜，也需要先詢問你？

## 13–16｜衝突與修復

### 13 `know-repair-expression`

**最近一個月，對親近的人感到不滿時，你最常先怎麼表達？**

- A．直接說出哪件事讓我不舒服
- B．先整理想法，再找時間說
- C．先用文字說明
- D．當下沒有說出來，之後也不一定提起

另提供：尚未經歷（最近一個月沒有這個情境）。

討論提示：什麼場合或開場方式，會讓你比較容易把不滿說清楚？

### 14 `know-repair-pause`

**發生爭執、需要暫停時，你比較希望怎麼安排？**

- A．短暫休息後，接著談同一個問題
- B．先分開休息，約定當天再談
- C．留到隔天，約好時間再談
- D．先用文字整理，再約時間談

討論提示：暫停期間，你希望維持怎樣的聯絡？如果需要延後，要怎麼說？

### 15 `know-repair-apology`

**對方的行為讓你受傷後，在道歉過程中，你最希望先聽到什麼？**

- A．清楚說出哪個行為需要負責
- B．說明理解這件事對我的影響
- C．提出下次會怎麼調整
- D．先讓我說完我的感受

討論提示：除了說出口，之後哪些行動對你也很重要？

### 16 `know-repair-feedback`

**對方想告訴你一件希望你調整的事，你最希望怎麼收到這個訊息？**

- A．當下私下簡短指出
- B．事先約一段時間，好好談
- C．先傳文字，讓我有時間整理
- D．先問我現在能不能談，再決定時間與方式

討論提示：有哪些說法會讓你比較難聽見原本的重點？不必重述傷人的經歷。

## 17–20｜自主與界線

### 17 `know-boundaries-alone`

**當你明確說想獨處時，你希望對方接下來怎麼做？**

- A．等我主動聯絡
- B．和我約好下次聯絡的時間
- C．可以留一句關心，不需要我立即回覆
- D．在事先約好的時段，簡短問我是否想恢復聯絡

討論提示：如果需要延長獨處時間，你願意用什麼方式讓對方知道？

### 18 `know-boundaries-phone`

**對於與交往對象分享手機密碼，你目前比較接近哪個想法？**

- A．各自保留，不需要交換
- B．緊急需要時可以提供，平常不使用
- C．可以交換，但查看內容前仍要詢問
- D．可以交換，也接受彼此直接查看

討論提示：知道密碼後，是否仍有需要另行取得同意的內容，例如其他人的私人訊息？

### 19 `know-boundaries-updates`

**當你的行程改變、但不影響兩人原本約定時，你比較希望怎麼告知對方？**

- A．不需特別說，聊天時再分享
- B．方便時傳一句簡短更新
- C．事先說明大致去向與時間
- D．先由雙方約定哪些變動需要告知

討論提示：哪些資訊是出於關心想知道，哪些是你不希望被要求提供的？

### 20 `know-boundaries-friends`

**如果開始交往，對於各自和朋友單獨相處，你目前比較希望怎麼安排？**

- A．各自安排，不需要逐次告知
- B．先告知大致安排，不需先取得同意
- C．先談好在意的情境，再各自安排
- D．每次先討論雙方的感受與安排

討論提示：哪些具體互動需要另談界線？以行為討論，不按朋友的性別或性向判斷。

## 21–24｜脆弱與支持（主動選擇）

不要求透露創傷、病史、秘密或特定人物。討論提示也可以不聊；跳過不代表不信任。

### 21 `know-vulnerability-hard-topic`

**如果願意分享，目前哪一類事情比較難向親近的人開口？**

- A．我對自己的不確定或沒自信
- B．我需要幫忙的地方
- C．我對這段關係的疑問
- D．我犯錯或做得不如預期的事情

討論提示：不必說事情本身，只談什麼回應會讓你比較願意開口。

### 22 `know-vulnerability-recognition`

**當你覺得自己做得不夠好時，你最希望對方先注意到什麼？**

- A．我已經付出的努力
- B．我面對的限制與負擔
- C．我正在學習或改變的地方
- D．我仍然有能力處理的部分

討論提示：有沒有一句你比較願意聽到的話？也可以只指出不希望聽到的說法。

### 23 `know-vulnerability-tears`

**如果你在對方面前哭了，你目前最希望對方先怎麼做？**

- A．安靜陪著，等我想說再說
- B．問我想不想說發生了什麼
- C．問我是否希望被擁抱或有其他接觸
- D．給我一些空間，約好稍後確認狀況

討論提示：如果當下的需要和平常不同，你希望怎麼讓對方確認？

### 24 `know-vulnerability-disclosure`

**當你準備談一件比較私人的事，你最希望先和對方確認什麼？**

- A．現在有沒有時間與心力聽
- B．這件事會不會被轉告別人
- C．我可以自己決定說到哪裡、何時停止
- D．對方會先聽，還是會提供建議

討論提示：這次分享的範圍由你決定，不需要用說出更多來證明信任。

## 25–28｜生活與未來

### 25 `know-life-spending`

- C．按雙方可負擔的程度協議比例

### 26 `know-life-housework`

- C．按各自擅長或較能接受的項目分配
- D．重要項目輪流做，避免長期固定由一人承擔

討論提示：誰負責注意、安排與提醒，也需要一起談嗎？

### 27 `know-life-family`

**對於把兩人的關係問題告訴家人，你目前比較希望怎麼處理？**

- A．主要在兩人之間處理，平常不向家人談細節
- B．可以談自己的感受，不提供對方的私人細節
- C．雙方同意分享範圍後，再向家人請教
- D．需要支持時，各自決定向家人談哪些內容

討論提示：哪些內容牽涉對方的隱私？若遇到傷害或安全問題，尋求外部協助不需要對方批准。

### 28 `know-life-location`

**如果有一個很吸引你的工作機會需要搬到外地，考慮關係安排時，你最想先釐清什麼？**

- A．是否能接受一段時間的遠距
- B．是否有機會一起搬遷
- C．有沒有留在原地的替代選擇
- D．雙方各自的生活與工作限制

討論提示：哪些事情現在能談，哪些需要知道更多條件才能決定？

## 29–32｜我們的關係（主動選擇）

可以用於曖昧、約會或已交往；回答不代表同意交往、承諾未來或必須推進關係。

### 29 `know-us-enjoy`

**以最近一個月的相處來說，你目前最珍惜哪個部分？**

- A．可以自然分享日常
- B．一起做事或出遊的感覺
- C．能談比較深入的想法
- D．各自有空間，也能保持聯繫

另提供：尚未經歷（最近一個月沒有足夠的相處）。

討論提示：如果願意，可以說一個小例子；對方也可以說自己注意到什麼。

### 30 `know-us-pace`

- D．先降低相處頻率，留時間確認自己的想法

討論提示：你說的「維持、增加或降低」，具體指什麼？這題的回答不要求另一方立刻答應。

### 31 `know-us-discuss-next`

**如果要讓這段關係繼續發展，你最想先談清楚哪一件事？**

- A．聯絡與見面的安排
- B．親近與個人空間的界線
- C．對關係承諾的理解
- D．意見不同時的處理方式

討論提示：有哪一件可以先從小範圍開始談，而不用一次決定全部？

### 32 `know-us-understand`

**在目前這段關係裡，你最希望接下來多了解哪一部分？**

- A．彼此的日常與生活習慣
- B．需要關心時，希望怎麼被對待
- C．意見不同時，怎麼溝通
- D．對關係與未來的期待

討論提示：有沒有一件最近發生的事，讓你想多了解這一部分？也可以直接選下一次想聊的題組。

## 預計流程與工程邊界

目前只有文件，沒有新的 Request / Data Flow（請求與資料流）。內容製作流程：原清單歸納 → 本稿 → 逐題審閱與來源查核 → 自願試答與理解回饋 → 核定內容版本 → 另行接入及驗證。

預計產品流程：

```text
選一至兩個題組 → 固定本輪題目、選項與分享規則版本
  → A 各題選答或明確暫不分享 → 確認提交 → 邀請 B
  → B 回答相同題目並確認提交
  → 後端確認雙方完成 → 並排呈現可分享答案與未分享狀態
  → 自選討論提示；不產生契合總分
```

接入前需設計題組選擇、明確跳過、提交完整性與分享欄位，同步 Node store／D1 store 驗證及回傳。不能直接放寬所有測驗的缺答條件；core-values 計分與舊 snapshot 保持原規則。A／B 回答同一輪固定題目，不各自抽到不同題目。

首版結果只並排選項與提供提示，不需「相同選項比例」。相同可能出於不同原因，差異也可能可以協調。「猜猜你」模式留待後續：另存本人答案與對對方的猜測，另定猜中規則；暫不分享等狀態不參與猜中判定，不混成關係品質分數。

## 審閱、除錯與自行修改

- 選項都不符合：記錄題目 ID、缺少情境與措辭問題，不要求私人故事。「其他」只是出口；先縮小情境再補選項。
- 多項同時符合：檢查是否明確問「最優先」且只問一件事；合併重疊選項或拆題，不能默默改成多選後沿用原比較。
- 有被迫分享的感覺：查題組是否主動選擇、暫不分享入口、提示是否追問秘密；移除追問或暫停該題，不給不分享負面解讀。
- 文件已改但網站沒出現：這是預期，本稿未被 src 匯入。用 `rg -n 'getting-to-know-you|know-care-support' docs src server cloudflare` 確認位置，不需改部署或清資料庫。
- 未來解鎖前出現對方答案：先查 Network 的 status／邀請 API 回傳及後端授權，不只看畫面。解鎖後仍出現不該分享的選項則查答案狀態、後端輸出欄位與快照；不把私人憑證或答案放進 log。

修改範例：若 09 題缺少「幫我處理眼前的小事」，先判斷是否與「整理問題與下一步」不同，再調整該題選項、提示、記錄原因並升候選版本。保持題目 ID 可追蹤；接入時給選項語意 ID，不以 A–D 作永久識別或分數。已發布題目改選項需升測驗版本，保留舊回合快照。

本稿為候選內容單一來源；接入後明確指定資料檔來源，避免手動維護兩份。歸屬或分享政策變更同步 [產品文件](../product.md)，新增研究主張同步 [研究文件](../research.md)。程式接入需跑 `npm run check`、`npm run build` 及相關畫面／雙人授權驗證，不能以文件檢查替代。
