## 定位與範圍

兩人各自選擇最接近自己的答案，揭曉後聊聊原因，認識日常、支持需求、界線與關係期待。適用交往前與交往中，不預設已婚、同居、排他關係或任何性別／性向；生育不在本版範圍。

使用者提供的開放式問答清單是內容起點。八面向是編輯分類，不是八種人格或經驗證量表；32 題與討論提示均為本站自編。本稿補充核心價值探索，不併入 PVQ-RR 的 57 題或相近度計算。

本稿屬「雙人問答｜從一個問題開始靠近」，與「主題測驗｜有系統地了解彼此」分開入口。兩者都可用選擇題；問答提供題目層次的共同點、差異與具體嘗試，測驗依各自有依據的題組與規則整理面向。分類不等於驗證標章，也不以有無分數判斷。

### 一次四題的預計體驗

題組列表顯示八張可各自開始的卡片，各標「四題」與內容深度。選一組後，填答進度顯示「第 1／4 題」，不是「第 1／32 題」。四題都已選答案或明確暫不分享即可提交；雙方完成後就能看這一輪的整理，不需等待其他七組。

結果頁提供「回題組列表」及可選的「再玩一組」。下一組是另一輪，不增加本輪題數、不清除已完成結果、不強制續玩。每輪固定題組 ID、四個題目 ID、內容／結果規則版本，A／B 回答同一組；B 接受邀請前知道本組主題與分享範圍，可以不加入。

所有整理只描述本組可分享的答案；四題不足以推論整體人格、完整關係或八面向總覽。選哪組與選四題是依填答負擔的產品選擇，尚未實測時間或證明四題比八題效果更好。

## 共用作答與分享規則（待接入）

引導：「選最接近你目前想法的一項。可能有好幾項符合，先選在這個情境下最優先的一項；沒有標準答案，回答也不等於答應對方。」

每題 A–D 是具體選擇，另共用以下出口，不要求補寫文字：

- 「其他較接近我的做法」：已有想法，但 A–D 沒涵蓋。
- 「沒有固定偏好，會依情境改變」：知道自己的想法隨條件而變。
- 「尚未想清楚」：目前尚無明確答案。
- 題目標有「尚未經歷」時另提供該選項；假設期待題仍能回答，不強迫用未經歷作答。
- 「這題目前不適用」：情境不適合本人，不要求原因。

另提供「暫不分享這題」操作，與答案分開：清除本題已填選項，結果只顯示「未分享」，不揭露先前選擇或要求原因；提交前明說對方會看見此狀態。實作必須由後端保護，不能只在前端隱藏。

未答、尚未想清楚、尚未經歷、不適用、暫不分享是不同狀態。本題組預計每題已選答案或明確暫不分享才能提交，未答仍不能提交；不套用核心價值的數值計分、不填零。現有 API 尚不支援本稿的暫不分享契約。

討論提示在揭曉後提供，不必在網頁輸入或上傳故事。私密題組可以整組不選，已選題組內仍可暫不分享。未分享、不適用、未經歷、尚未想清楚不列為共同偏好或差異；「其他」或「依情境」相同也不能推論具體偏好相同。

- C．我待人或思考的方式

- D．保留身體距離，用陪伴表達

## 13–16｜衝突與修復

### 13 `know-repair-expression`

**最近一個月，對親近的人感到不滿時，你最常先怎麼表達？**

- A．直接說出哪件事讓我不舒服
- B．先整理想法，再找時間說
- C．先用文字說明
- D．當下沒有說出來，之後也不一定提起

另提供：尚未經歷（最近一個月沒有這個情境）。

討論提示：什麼場合或開場方式，會讓你比較容易把不滿說清楚？

### 14 `know-repair-pause`

**發生爭執、需要暫停時，你比較希望怎麼安排？**

- A．短暫休息後，接著談同一個問題
- B．先分開休息，約定當天再談
- C．留到隔天，約好時間再談
- D．先用文字整理，再約時間談

討論提示：暫停期間，你希望維持怎樣的聯絡？如果需要延後，要怎麼說？

### 15 `know-repair-apology`

**對方的行為讓你受傷後，在道歉過程中，你最希望先聽到什麼？**

- A．清楚說出哪個行為需要負責
- B．說明理解這件事對我的影響
- C．提出下次會怎麼調整
- D．先讓我說完我的感受

討論提示：除了說出口，之後哪些行動對你也很重要？

### 16 `know-repair-feedback`

**對方想告訴你一件希望你調整的事，你最希望怎麼收到這個訊息？**

- A．當下私下簡短指出
- B．事先約一段時間，好好談
- C．先傳文字，讓我有時間整理
- D．先問我現在能不能談，再決定時間與方式

討論提示：有哪些說法會讓你比較難聽見原本的重點？不必重述傷人的經歷。

## 21–24｜脆弱與支持（主動選擇）

不要求透露創傷、病史、秘密或特定人物。討論提示也可以不聊；跳過不代表不信任。

- D．我仍然有能力處理的部分

### 24 `know-vulnerability-disclosure`

- A．現在有沒有時間與心力聽

- C．我可以自己決定說到哪裡、何時停止
- D．對方會先聽，還是會提供建議

## 預計流程與工程邊界

### 結果整理與建議（已確認方向，規則候選）

結果由逐題可分享的答案出發，不由八面向推算人格。每項整理附題目與雙方實際選項，讓使用者知道為何出現；建議可分為「給你、給對方、給兩人」，不必每題硬湊三則。

1. **共同點**：同一題雙方選相同的具體選項，描述「本輪都選擇……」。不把「其他／依情境」當成具體偏好相同，不說兩人原因相同或已達成協議。
2. **差異**：同一題選不同的具體選項，忠實指出期待或做法不同；不把差異判成衝突、高風險或不適合。
3. **個別建議**：根據對方明確表達的期待，提出本人可詢問或嘗試的做法；不把需求題當成實際行為題。例如 09 題選「想被傾聽」不能推論本人也會先傾聽別人。
4. **雙人建議**：提供一個小範圍、雙方自願的安排，包含確認情境與是否接受，不宣稱一定有效。身體接觸、隱私與獨處等界線不要求折衷、交出資訊或證明信任。
5. **資料不足**：任一方尚未想清楚、未經歷、不適用或暫不分享，不生成共同點／差異或針對該人的推論；可提供通用的可選聊天提示。未分享者不被追問理由。「其他／依情境」只列答案與詢問提示，不套具體選項配對建議。

建議屬本站自編應用，沒有被上述研究直接驗證。未來每則需有規則 ID、題目 ID、選項語意 ID、觸發條件、解讀邊界、版本及來源狀態；不依 A/B/C/D 的順序計分，不只憑兩個答案由生成式模型臨時判定人格。測驗的多題面向結果則依其獨立規則辦理。

預計產品流程：

```text
選一個四題題組 → 固定本輪題組、四題、選項與分享規則版本
  → A 各題選答或明確暫不分享 → 確認提交 → 邀請 B
  → B 回答相同題目並確認提交
  → 後端確認雙方完成 → 並排呈現可分享答案與未分享狀態
  → 整理共同點／差異 → 個別與雙人嘗試建議 → 自選討論提示
  → 不產生契合總分
  → 可回列表結束；想再玩另一組時另開一輪
```

接入前需設計題組選擇、明確跳過、提交完整性與分享欄位，同步 Node store／D1 store 驗證及回傳。不能直接放寬所有測驗的缺答條件；core-values 計分與舊 snapshot 保持原規則。A／B 回答同一輪固定題目，不各自抽到不同題目。

四題規格只適用於本問答內容，不能把既有 57 題核心價值截成四題。題組與完整性檢查以本輪快照中的題目為準，不拿整份 32 題當每輪提交條件；本輪結果也不混入其他回合或未作答題組。

首版結果提供並排選項、共同點／差異、具體嘗試建議與提示，不需「相同選項比例」。「猜猜你」模式留待後續：另存本人答案與對對方的猜測，另定猜中規則；暫不分享等狀態不參與猜中判定，不混成關係品質分數。

## 審閱、除錯與自行修改

- 選項都不符合：記錄題目 ID、缺少情境與措辭問題，不要求私人故事。「其他」只是出口；先縮小情境再補選項。
- 多項同時符合：檢查是否明確問「最優先」且只問一件事；合併重疊選項或拆題，不能默默改成多選後沿用原比較。
- 有被迫分享的感覺：查題組是否主動選擇、暫不分享入口、提示是否追問秘密；移除追問或暫停該題，不給不分享負面解讀。
- 文件已改但網站沒出現：這是預期，本稿未被 src 匯入。用 `rg -n 'getting-to-know-you|know-care-support' docs src server cloudflare` 確認位置，不需改部署或清資料庫。
- 未來解鎖前出現對方答案：先查 Network 的 status／邀請 API 回傳及後端授權，不只看畫面。解鎖後仍出現不該分享的選項則查答案狀態、後端輸出欄位與快照；不把私人憑證或答案放進 log。
- 共同點或建議不符合答案：依序核對題目與選項語意 ID、特殊狀態、觸發規則 ID、版本及你／對方方向；尤其檢查是否把「希望收到」誤當「實際提供」。錯誤建議先停用該規則，不改寫原答案或重新計分。
- 未來做完四題卻不能提交、進度顯示 32 題：先查題組 ID 與本輪快照是否只有該組四題，再查完整性規則是否誤用全題庫；前端改分母不能解決後端仍要求 32 題的問題。

修改範例：若 09 題缺少「幫我處理眼前的小事」，先判斷是否與「整理問題與下一步」不同，再調整該題選項、提示、記錄原因並升候選版本。保持題目 ID 可追蹤；接入時給選項語意 ID，不以 A–D 作永久識別或分數。已發布題目改選項需升測驗版本，保留舊回合快照。

本稿為候選內容單一來源；接入後明確指定資料檔來源，避免手動維護兩份。歸屬或分享政策變更同步 [產品文件](../product.md)，新增研究主張同步 [研究文件](../research.md)。程式接入需跑 `npm run check`、`npm run build` 及相關畫面／雙人授權驗證，不能以文件檢查替代。

結果修改範例：把 09 題「一起想」提示改成先詢問是否需要建議，應改結果規則與樣稿並升結果規則版本；不因此改 09 題本人選項。接入時驗證 A/A、A/B、B/A、特殊狀態與暫不分享，確認互換角色及無資料分支都正確；八面向分類不可直接充當八個分數。

題組修改範例：想在關心題組增加一題時，先決定替換哪一題，維持本組四題，更新題組／內容版本與受影響的結果條件；舊回合仍用原快照。若改成五題，需另核定單輪題數與介面，不能只在清單追加就讓本輪負擔變多。
