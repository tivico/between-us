## 作答引導與共用出口

直接回答自己的做法或期待。「你」是你，「對方」是這輪一起回答的人。行為題只回想最近一個月與這輪對方的經歷，不用過去伴侶或想像情境代答；期待題回答目前希望收到的方式。單選通常第一步／最優先的一項，沒有標準答案。每題可選其他、依情況改變、尚未想清楚、不適用或暫不分享。雙方完成後，你願意分享的選項與特殊狀態會讓對方看到；暫不分享只顯示未分享，不要求補寫私人故事。選答不等於同意履行某項安排。

以下每題列四個主要選項，另外全部都提供：

- 其他方式比較接近我（`other`）
- 沒有固定方式，會依情況改變（`varies`）
- 目前還沒想清楚（`uncertain`）
- 這題目前不適用（`not-applicable`）
- 這題我暫不分享（`not-shared`）

所有「我的做法」題另有「最近一個月，和對方沒有遇過這個情況」。尚未選是未答；暫不分享是已選的分享狀態，不要求用私人故事補答。

「通常第一步」與「最優先」只描述本情境的排序，不代表其他方式不重要。沒有明確回應可選其他，選項重疊或不足需試答修訂。

| 準備好時再聯絡我；不先約時間 | 可以確認等待期間是否需要其他訊息，以及由誰在準備好時聯絡。 |
| 先問我哪些時段方便，再一起選 | 可以各提能談的時段，確認雙方的體力與安排，再選一個時間。 |

一起確認：如果到約定時間仍沒準備好，你希望怎麼重新安排？

### 暫停期間怎麼聯絡

期待題：`comm-pause-contact-want`；做法題：`comm-pause-contact-do`。

同類閱讀：這個方向的暫停期間聯絡選到同一類；仍可確認必要事項與日常問候的界線。

不同方式閱讀：兩人對暫停期間的聯絡選擇不同；可以確認哪些聯絡可接受，不要求單方放棄需要的空間。

| 期待方選的方式 | 給提供回應者的可選提案 |
| --- | --- |
| 暫時不聯絡，等重新開始時再說 | 可以確認暫停聯絡的範圍及必要事項的處理方式，不把安靜直接解讀成冷淡。 |
| 只聯絡眼前需要處理的事情 | 可以確認哪些是眼前必要事項，讓雙方知道這段期間如何聯絡。 |
| 簡短問候，但先不談原本的議題 | 可以確認彼此是否接受簡短問候，以及什麼內容會讓人感到又被拉回討論。 |
| 維持平常的日常聯絡，但先不談原本的議題 | 可以確認哪些日常聯絡仍舒服，以及是否需要比平常少一點。 |

一起確認：這段期間什麼聯絡讓你自在，什麼聯絡會讓你覺得仍在討論？

### 重新開啟討論

期待題：`comm-restart-want`；做法題：`comm-restart-do`。

同類閱讀：這個方向的重啟方式選到同一類；可以確認再次談的範圍與當下意願。

不同方式閱讀：一方希望的重啟方式與另一方自述不同；可先確認眼前需要的是狀態確認、回顧還是處理下一步。

| 期待方選的方式 | 給提供回應者的可選提案 |
| --- | --- |
| 先問我現在是否能繼續談 | 可以先確認當下能不能繼續談；不方便時再安排，不把拒絕當成不願處理。 |
| 先確認上次談到哪裡 | 可以各說一句記得談到的地方，再選這次先談的一件事。 |
| 先說對方現在的感受 | 可以分享願意說的當下感受，讓另一方有機會補充或詢問。 |
| 先提出這次想處理的一個重點 | 可以先提一個重點，再確認另一方是否也願意從這裡開始。 |

一起確認：這種開頭會幫你接回哪一部分？有沒有什麼事還想先確認？

### 說話讓對方不舒服之後

期待題：`comm-hurt-response-want`；做法題：`comm-hurt-response-do`。

同類閱讀：這個方向希望收到的第一步與另一方自述選到同一類；這不代表已原諒或影響已處理。

不同方式閱讀：兩人對說話造成不舒服後的第一步選擇不同；可以分開原意、影響與改說法，不要求立即原諒。

| 期待方選的方式 | 給提供回應者的可選提案 |
| --- | --- |
| 先承認對方的說法對我造成的影響 | 可以先回應已被說出的影響，不要求受影響的一方立刻原諒或安慰自己。 |
| 先說明對方原本想表達的意思 | 可以說明原意，也確認另一方是否想先談影響；原意與造成的感受可能不同。 |
| 先問我是在哪一部分感到不舒服 | 可以只問另一方願意分享的部分，不要求用私人細節證明感受。 |
| 先提出對方想怎麼換一種說法 | 可以試說一個新的表達方式，再讓另一方決定是否願意回應；不用換字取代處理影響。 |

一起確認：原本的意思與你受到的影響，哪部分希望先被知道？

### 後續安排怎麼確認

期待題：`comm-follow-up-want`；做法題：`comm-follow-up-do`。

同類閱讀：這個方向的後續確認選到同一類；可以確認一個願意試的安排與調整出口。

不同方式閱讀：兩人對後續確認的選擇不同；可以談固定回看、試過再談與有需要才談，各自需要什麼。

| 期待方選的方式 | 給提供回應者的可選提案 |
| --- | --- |
| 先約一個時間，再一起看看調整後的情況 | 可以約一個回看時間，確認做得到的部分與需要調整的部分，不把回看當成考核。 |
| 等實際試過一次，再一起談感受 | 可以先確認一次小範圍嘗試，做完再各說感受；沒有發生機會時另作安排。 |
| 遇到不合適或需要調整時，再提出來談 | 可以確認需要重談時如何提出，不把沒有再次提出當作已滿意。 |
| 先確認下一個具體行動；暫時不另約回看 | 可以先各確認一個願意做的行動，之後若有困難再聯絡，不把選答當成已答應執行。 |

一起確認：怎麼確認會讓你覺得是在一起調整，而不是被檢查？

## 整體閱讀與摘要規則

這份整理比較目前期待與另一方最近一個月的自述做法。相同選項不表示期待已被滿足；不同選項不表示衝突。可以先確認這個選擇在什麼情境成立，再決定是否想試一個小安排。

每段依題序選第一個有可比較差異的配對作為可選聊天入口；無差異時選第一個可比較相同的配對；全為特殊狀態則明示沒有可比較配對、不硬湊。題序是導航優先順序，不代表差異大小、重要性或衝突嚴重程度。若同一配對雙向都有資料，均顯示，不能只留下其中一個方向。最多四個入口，完整資料不刪除。

建議交流步驟：

1. 確認摘要說的是哪個方向與實際選項
2. 各自說這個選擇的意思與適用情境，不必分享私人事件
3. 確認先前不知道的需要或限制
4. 自願選一個小安排，確認做不到時怎麼調整；也可以不安排

### 判斷範例（虛構設計例，不是使用者答案）

| 情境 | 輸入 | 預期結果 |
| --- | --- | --- |
| 雙向同類 | A timing-want=check-now、B timing-do=check-now；B timing-want=set-time、A timing-do=set-time | 兩個方向各為同類，但不稱已滿足或完美溝通。 |
| 一方向不同、另一方向同類 | A timing-want=set-time、B timing-do=right-away；B timing-want=check-now、A timing-do=check-now | A期待←B做法為不同；B期待←A做法為同類，兩方向分開顯示。 |
| 雙方都其他 | A timing-want=other、B timing-do=other | context-only、advice:null，不判同類。 |
| 沒有本輪經歷 | A timing-want=set-time、B timing-do=not-experienced | context-only、advice:null，不推定B不願談；另一方向獨立判斷。 |
| 未分享 | A timing-want=not-shared、B timing-do=right-away | 只顯示未分享狀態，不產生給A或B的本方向提案，不回推A原偏好。 |
| 未答 | A任一題未選 | 本輪未完成，不解鎖結果；不填零或替答。 |

本輪只有文件；JSON 不會自動進入 `src/content/quizzes.ts`，也不會被 Node／D1 或網站載入。工程查核不增加人類試答人數，研究支持概念不等於24題或提案已驗證。

## 逐題理解回饋方式

自願試答者可先讀完整選項；不必交出私人選答。觀察者可記下：題目 ID、對題意的改述、你／對方是否清楚、是否需要猜過去或未來、重疊／遺漏選項、是否能選第一步、是否願意分享與大致負擔。可以停下或只審閱一段；不因單一好評宣稱全題已驗證。

建議空白紀錄欄位：

| 題目 ID | 試答者改述題意 | 選項重疊／遺漏 | 第一個動作是否能選 | 時間窗是否有經歷 | 可讀性／分享壓力 | 修訂提案與狀態 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

先處理「不知道怎麼選」的原因：沒遇過用沒有經歷，方式常變用依情況改變，沒有合適內容用其他；若多個主要選項代表同一件事，修訂分類。結果回饋再確認摘要是否忠實、是否把提案當成義務，以及是否只靠差異就推定衝突。私人故事與原始選答不進 Git。
