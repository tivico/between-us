# 靠近，也保留自己：研究與內容藍圖

更新／查核日期：2026-10-13。原創候選 `0.1.0`、結果規則候選 `candidate-0.1.0`。使用者已選定接著做陪伴、獨處與界線；沿用直接問「你」的題型，不用人物相似程度描述。本輪完成[12題第一輪候選稿](space-boundaries-candidate.md)與[JSON](space-boundaries-candidate.json)，正式題數／工具與結果規則尚待核定，網站仍為 `0.12.0`、`space-boundaries` 為 `planned`。

## 產品目的與分工

讓兩人認識「哪些相處讓我自在、自己待著時想保留什麼、私人資訊願意分享到哪裡，以及各自安排怎麼聯絡」。不把界線鬆緊當信任、親密或健康分數；不要求用密碼、定位、照片或讓步證明愛。

現有 `know-boundaries` 四題問答是聊天入口，溝通24題聚焦討論歷程，日常三觀八情境聚焦生活取捨。本主題專門區分本人分享範圍、一般相處偏好與對方自述做法，避免把不同性質的答案全套成「相同／不同」。第一輪沒有加入身體接觸、定位、居住空間或物品使用；它們可能需要不同同意與情境規則，後續另定範圍。生育不在範圍。

不限性向與性別認同，不預設同居、婚姻、排他關係或關係已公開；朋友不按性別／性向分類。行為題只回想最近一個月和本輪對方的經歷，交往前沒有情境就明示沒有經歷，不能猜未來或以過去伴侶代答。時間窗與12題只是本輪編輯設計，沒有最佳題數或完成時間的研究主張。

## 三種答案的不同讀法

| 資料性質 | 白話意思／本稿欄位 | 可以整理什麼 | 不能推論什麼 |
| --- | --- | --- | --- |
| 相處偏好 | `preference`：目前想怎麼相處或獨處 | 同題選擇並排，主要選項時可說相同／不同 | 自主高低、孤單、依附類型、最佳時間比例 |
| 本人界線 | `owner-boundary`：本人現在願意的範圍 | 個別忠實呈現範圍與尚未同意的部分 | 契合／信任分數、應有的折衷、實際存取許可 |
| 期待與做法 | `partner-expectation`／`self-behavior` | 同一情境的 A期待對B做法、B期待對A做法 | 實際已滿足、一定尊重／不尊重、誰較會相處 |
| 情境與更新流程 | `self-behavior`單獨閱讀／`process-preference` | 最近自述與希望怎麼更新安排 | 憑一題診斷監控、把未來安排當已同意 |

重要取捨：**本人界線不作配對相似度，也不要求交集或折衷。** 例如本人現在不願讓對方操作手機，另一方曾按過去約定使用，後者不能覆蓋前者。能解鎖、曾借用或這輪選了某一範圍，都不能被產品解讀為某次新用途已獲准。這是本站明確的分享／結果設計原則；不宣稱研究已驗證這個頁面順序或本題庫。

結果先看現在願意的範圍，再看相處偏好、兩組雙向配對及願意聊的情境；拒絕、不想現在回答、未決定或未分享不能被另一方要求覆蓋。未分享取代原選項，不只畫面隱藏。其他／依情況改變／不適用／沒經歷均保留情境，配對提案為null，不判一致或衝突。單向相同不等於另一方向相同，兩人都選其他不是相同做法。

候選附8種必須審閱的案例，包括單方不借手機、未確認用途、不公開照片、其他／沒有經歷、雙向聯絡差異、求助出口與過去／現在界線不同。這些是設計情境，不是使用者答案或已運行的分析測試；另一方的未收集偏好不能捏造。一般分享規則不擴充為限制本人尋求支持，提案不要求交出私人故事或他人可識別細節。

## 執行流程與維護交接

本輪只有內容文件，沒有Request／Data Flow、API或私人資料讀寫。實際工作流程為：公開研究／工具入口查核 → 記錄來源與支持範圍 → 12題候選JSON → 可讀Markdown稿 → 逐題編輯查核與回饋模板。人類理解回饋、正式量測與提案效果另外完成。

未來核定後才走：`src/content/quizzes.ts`註冊主題 → 內容轉換檔建立題庫／界線設定 → 每輪snapshot固定版本 → Node／D1保存本人分享狀態 → 授權且雙方提交後的results產生結果 → 前端先讀界線再看配對。這是預定流程，尚未實作；不能只把status改ready或直接重用communication分析而忽略本人界線。

壞掉時的排查順序：

1. 題目難選：先請審閱者改述「你／對方」及題意，分辨沒經歷、選項重疊或多個都優先，再看是否混問用途／許可／實際做法；不要歸因為不懂心理學。
2. 結果把隱私當契合：查`perspective`與`boundary.owner/refusalOptionIds`；本人界線不得進同類／不同或交集。查問的是同意範圍還是自述，能力／曾經使用不是許可。
3. 期待與做法反向：查`resultPlan.crossPairs`的wanted／provided題號，A希望收到的回應對B提供，B對A；手機做法題沒有crossPair，不能按選項順序比較。
4. 文獻變成過強主張：查sources.readScope與limitations。沒有本題直接來源就保留自編，不用獨處研究的15分鐘定規則，不以裝置分享率說「應該開放」。
5. 找不到網站入口：目前仍應籌備中；安全指令 `rg -n 'space-boundaries|靠近，也保留自己' src/content/quizzes.ts docs README.md`。JSON不會自動上線；本輪不應修資料庫或部署來讓草稿出現。

日後修改例子：要把05題「只在明確答應的用途與期限」改白話，先改JSON的`space-phone-boundary/agreed-purpose`，確認仍是本人同意範圍，不改成只要知道密碼即可使用；核對`boundary.exceptionPolicy`與結果閱讀、同步Markdown及候選版本。若新增「定位分享」需獨立題與用途／可見者／停止分享的規則，不把定位默默塞入手機借用題。正式接入後，改題／提案升工具內容版，改分析另加版本並保留舊分支與快照。

理解回饋優先看：獨處用途與需要是否分清、借用用途／期限是否白話、照片公開與私下傳送是否被混為同意、臨時邀請四選項是否重疊、12題是否太窄。可自願只審閱一段，不蒐集私人選答；目前試答人數為零，不能以編輯審閱稱認知訪談完成。
